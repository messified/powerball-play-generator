# Backtest Data Structures Documentation

## Overview

This document describes the three core data structures used in the walk-forward backtesting system: `BacktestResult`, `BacktestSummary`, and `BacktestStepResult`. These structures work together to represent both individual step results and aggregated performance metrics.

---

## 1. BacktestStepResult

**Purpose**: Represents the results from a single walk-forward step - one future draw prediction using historical training data up to that point.

**Location**: `src/app/services/backtest.service.ts` (lines 15-29)

**Structure**:

```typescript
export interface BacktestStepResult {
  step: number;                    // Chronological step index (0-based)
  trainingSize: number;            // Number of historical draws used for training
  testDraw: PowerballDraw;         // The actual draw being tested against
  predictions: {                   // Array of predictions from each strategy
    strategy: string;              // Strategy name: 'legacy', 'prediction', or 'ai'
    tickets: string[][];           // All tickets generated by this strategy
    bestMatch: {                   // Best matching ticket from this strategy's batch
      whiteHits: number;           // Number of white ball matches (0-5)
      powerballHit: boolean;       // Whether powerball matched
      matchedTicket: string[];     // The actual ticket that achieved this match
    };
  }[];
  timestamp: Date;                 // When this step was evaluated
}
```

**Key Characteristics**:

- Each step represents one future draw prediction
- Training size increases with each step (walk-forward expansion)
- Contains actual test draw for context (`testDraw`)
- Each strategy generates multiple tickets, but only the `bestMatch` is tracked
- `bestMatch` is determined by comparing all tickets against the actual draw:
  - Best white hits (0-5)
  - If tied, preference given to powerball hit
- Steps are chronologically ordered by `step` number

**Example**:

```typescript
{
  step: 5,
  trainingSize: 105,
  testDraw: {
    draw_date: '2024-01-15',
    winning_numbers: '01 15 23 45 67 10',
    multiplier: '2'
  },
  predictions: [
    {
      strategy: 'legacy',
      tickets: [['01', '02', '03', '04', '05', '10'], ...],
      bestMatch: {
        whiteHits: 2,
        powerballHit: true,
        matchedTicket: ['01', '15', '20', '30', '40', '10']
      }
    },
    {
      strategy: 'prediction',
      tickets: [...],
      bestMatch: { whiteHits: 1, powerballHit: false, matchedTicket: [...] }
    }
  ],
  timestamp: new Date('2024-01-16T10:30:00Z')
}
```

## 2. BacktestSummary

**Purpose**: Aggregated performance metrics computed from all walk-forward steps, providing strategy-level totals and averages.

**Location**: `src/app/services/backtest.service.ts` (lines 31-50)

**Structure**:

```typescript
export interface BacktestSummary {
  totalSteps: number;              // Total number of walk-forward steps
  strategies: {                    // Object keyed by strategy name
    [strategyName: string]: {
      totalWhiteHits: number;      // Cumulative sum across all steps
      totalPowerballHits: number;  // Cumulative count (0 or 1 per step)
      averageWhiteHits: number;    // totalWhiteHits / stepCount (per-step mean)
      averagePowerballHits: number;// totalPowerballHits / stepCount
      bestWhiteHits: number;       // Maximum white hits in any single step (0-5)
      worstWhiteHits: number;      // Minimum white hits in any single step (0-5)
      perfectMatches: number;      // Count of steps with 5 white + powerball
      nearMisses: number;          // Count of steps with (4 white + powerball) or (5 white)
    };
  };
  overallMetrics: {
    totalPredictions: number;      // Total strategy predictions across all steps
    averageTicketsPerStep: number; // Average tickets generated per step
    totalTestDraws: number;        // Total test draws (typically equals totalSteps)
  };
}
```

**Key Characteristics**:

- **Totals are cumulative**: Sum across all steps (e.g., `totalWhiteHits`)
- **Averages are per-step means**: Calculated as `total / stepCount` (e.g., `averageWhiteHits`)
- **Best/worst represent extremes**: Single highest/lowest value across all steps
- **Perfect matches and near misses are rare-event counts**:
  - Perfect match: `whiteHits === 5 && powerballHit === true`
  - Near miss: `(whiteHits === 4 && powerballHit === true) || (whiteHits === 5)`
- All strategy metrics are directly comparable (same test draws, same step count)

**Calculation Logic** (from `generateSummary` method):

- Initializes stats for each strategy found in stepResults
- Iterates through all steps and predictions
- Aggregates: sums totals, tracks best/worst, counts rare events
- Calculates averages: `total / stepCount` for each strategy
- `totalPredictions` = sum of all strategy predictions (strategies × steps)
- `averageTicketsPerStep` = total tickets / total steps

**Example**:

```typescript
{
  totalSteps: 50,
  strategies: {
    legacy: {
      totalWhiteHits: 75,
      totalPowerballHits: 8,
      averageWhiteHits: 1.5,        // 75 / 50
      averagePowerballHits: 0.16,   // 8 / 50
      bestWhiteHits: 4,
      worstWhiteHits: 0,
      perfectMatches: 0,
      nearMisses: 2
    },
    prediction: {
      totalWhiteHits: 82,
      totalPowerballHits: 10,
      averageWhiteHits: 1.64,
      averagePowerballHits: 0.2,
      bestWhiteHits: 5,
      worstWhiteHits: 0,
      perfectMatches: 1,
      nearMisses: 3
    }
  },
  overallMetrics: {
    totalPredictions: 100,          // 2 strategies × 50 steps
    averageTicketsPerStep: 80,      // Average across all strategies
    totalTestDraws: 50
  }
}
```

## 3. BacktestResult

**Purpose**: Complete backtest result containing both the high-level summary and detailed step-by-step results, along with the configuration used.

**Location**: `src/app/services/backtest.service.ts` (lines 52-56)

**Structure**:

```typescript
export interface BacktestResult {
  summary: BacktestSummary;         // Aggregated metrics across all steps
  stepResults: BacktestStepResult[];// Individual step results (chronologically ordered)
  config: BacktestConfig;           // Configuration used for this backtest
}
```

**Key Characteristics**:

- **Complete picture**: Contains both aggregated summary and detailed step-by-step data
- **Chronological ordering**: `stepResults` array is ordered by `step` number (oldest to newest)
- **Configuration preserved**: `config` contains the exact settings used, enabling reproducibility
- **Relationship between structures**:
  - `summary` is computed from `stepResults` by the `generateSummary()` method
  - `summary.totalSteps` equals `stepResults.length`
  - `summary.totalTestDraws` equals `stepResults.length` (one test draw per step)
  - Each strategy's metrics in `summary` are aggregated from corresponding predictions in `stepResults`

**BacktestConfig Structure** (for reference):

```typescript
export interface BacktestConfig {
  initialTrainingSize: number;      // Starting training window size
  stepSize: number;                 // Draws to add per step (1 = walk-forward)
  holdoutSize: number;              // Future draws to test (usually 1)
  minTrainingSize: number;          // Minimum draws before testing
  strategies: string[];             // Strategies to test: 'legacy', 'prediction', 'ai', 'all'
  ticketsPerStrategy: number;       // Tickets generated per strategy per step
  maxSteps?: number;                // Optional limit on number of steps
}
```

**Example**:

```typescript
{
  summary: { /* BacktestSummary object */ },
  stepResults: [
    { step: 0, trainingSize: 100, testDraw: {...}, predictions: [...], timestamp: ... },
    { step: 1, trainingSize: 101, testDraw: {...}, predictions: [...], timestamp: ... },
    { step: 2, trainingSize: 102, testDraw: {...}, predictions: [...], timestamp: ... },
    // ... more steps
  ],
  config: {
    initialTrainingSize: 100,
    stepSize: 1,
    holdoutSize: 1,
    minTrainingSize: 50,
    strategies: ['all'],
    ticketsPerStrategy: 40,
    maxSteps: undefined
  }
}
```

## Data Flow

### How Data is Generated:

1. **Backtest Execution** (`runBacktest` method):
   - Sorts historical data chronologically
   - Iterates through walk-forward steps
   - For each step:
     - Trains on data up to `currentTrainingSize`
     - Generates predictions for all configured strategies
     - Evaluates predictions against the next draw (holdout)
     - Creates a `BacktestStepResult` and adds to `stepResults` array
     - Expands training window: `currentTrainingSize += stepSize`

2. **Summary Generation** (`generateSummary` method):
   - Takes `stepResults` array as input
   - Initializes stats objects for each strategy
   - Aggregates across all steps:
     - Sums totals (white hits, powerball hits)
     - Tracks extremes (best/worst white hits)
     - Counts rare events (perfect matches, near misses)
   - Calculates averages: `total / stepCount`
   - Returns `BacktestSummary` object

3. **Result Assembly**:
   - Combines `summary`, `stepResults`, and `config` into `BacktestResult`
   - Returns complete result object

## Relationships & Dependencies

### PowerballDraw Interface
`BacktestStepResult.testDraw` uses the `PowerballDraw` interface:

```typescript
export interface PowerballDraw {
  draw_date: string;        // ISO date string
  winning_numbers: string;  // Space-separated: "01 15 23 45 67 10"
  multiplier: string;       // Multiplier value (e.g., "2")
}
```

### Ticket Format

- Tickets are `string[][]` where each ticket is `string[]` with 6 elements:
  - First 5 elements: white balls (e.g., `['01', '15', '23', '45', '67']`)
  - 6th element: powerball (e.g., `'10'`)
- Numbers are zero-padded strings (e.g., `'01'` not `'1'`)

### Strategy Names

- `'legacy'`: Uses `PowerballService.generatePowerballPlay()` with `predictiveWeightedRandomPlay`
- `'prediction'`: Uses `PredictionService.generatePowerballPlay()` (higher-order Markov)
- `'ai'`: Uses `AiPowerballService.generateBatch()` (ML backend)

## Key Insights for Visualization

Based on the plan document, here are important considerations:

1. **Comparability**: All strategies in `summary.strategies` are directly comparable because they use the same test draws and same number of steps.

2. **Averages vs Totals**: For visualization, prefer showing averages (per-step means) rather than totals, as averages account for different step counts and are more meaningful.

3. **Time Series**: The `stepResults` array provides chronological data for time-series visualization. Each `stepResults[i]` represents step `i` in chronological order.

4. **Distribution Data**: To show distributions, extract `bestMatch.whiteHits` from each step's predictions and group by strategy.

5. **Rare Events**: Perfect matches and near misses are interesting outliers but should be framed as rare event frequencies, not success indicators.

6. **Variance**: The difference between `bestWhiteHits` and `worstWhiteHits` shows the range of outcomes, indicating variance/consistency.

7. **Sample Size**: `summary.totalSteps` (or `summary.overallMetrics.totalTestDraws`) is the sample size and should be prominently displayed.

## Usage Examples

### Accessing Strategy Metrics:

```typescript
const result: BacktestResult = await backtestService.runBacktest();
const legacyStats = result.summary.strategies['legacy'];
console.log(`Average white hits: ${legacyStats.averageWhiteHits}`);
```

### Iterating Through Steps:

```typescript
result.stepResults.forEach((step, index) => {
  console.log(`Step ${step.step}: Training size ${step.trainingSize}`);
  step.predictions.forEach(pred => {
    console.log(`  ${pred.strategy}: ${pred.bestMatch.whiteHits} white hits`);
  });
});
```

### Getting Distribution Data:

```typescript
const whiteHitsByStrategy: { [strategy: string]: number[] } = {};
result.stepResults.forEach(step => {
  step.predictions.forEach(pred => {
    if (!whiteHitsByStrategy[pred.strategy]) {
      whiteHitsByStrategy[pred.strategy] = [];
    }
    whiteHitsByStrategy[pred.strategy].push(pred.bestMatch.whiteHits);
  });
});
```
